# NBW V2 原生客户端开发交付

日期：2026-10-25。当前在 `feat/nbw-v2-native-20261025` 开发线，基于 `c8dd0ccd`。这是配套新 V2 后端的开发测试客户端，不是正式发布；版本仍为 `3.2.0 / code34`，测试包须以文件名和 SHA-256 区分，不能仅凭版本号辨认。

## 已实现的产品行为

- 正常合作模式下，符合外发范围的公开社区内容由服务器自动尝试同步。用户没有日常“不同步”或“仅本站”菜单项。
- 本站提交不等 NBW 或 AI，不以绑定、授权、分类加载或上游故障锁住普通本站发帖；同步失败不弹 Toast、不回滚本站内容。
- 新客户端请求使用 `X-ABDL-NBW-Protocol: 2`。NBW 能力、分类目录、同意和授权启动使用 `/api/app/*`；旧 NBW V1 登录、绑定和推荐调用不再用于新版链路。
- 分类目录由服务器缓存，会话级 repository 在启动时预取，五分钟 TTL、单飞、会话 generation 隔离，发帖页共享同一快照。
- 使用现有 miuix 0.9.3 的两级叠加菜单，一级 FID，二级 typeid。手动选择保留完整合法 ID；过期手动意图不会悄悄换成另一个板块。
- AI 分类由服务器在本站提交后执行。失败后只有账号明确同意过默认回退，且目录仍允许时，才使用闲聊 FID18 / typeid0。接受或拒绝回退是独立账号设置，不是“是否同步”开关，也不补发历史内容。
- 新授权只负责已登录本站账号的连接/重新授权，不声称保留旧匿名 NBW 登录流程。上游长期 token 不进入 App 或深链。
- `local_only` / `read_only` / `full` 能力与本站身份分离，不使用旧兼容假用户名推断授权。

## 生命周期修复

本轮独立审查后补充：

1. 列表过滤复制不可变调用参数，并同步底层数据、预载数据和显示条目，避免线程页传 `Collections.singletonList` 时崩溃。
2. 远端成功/错误回调在真正主线程交付点再次检查原会话和 generation，切换账号后的迟到结果不再交付。
3. 取消赞/收藏请求以独立、一次性 cleanup 清除正在执行标记并撤销未经确认的乐观状态；不伪称远端成功或失败，不向旧账号回调或弹错。
4. 最近搜索缓存识别 `acc_nbw_` / `post_nbw_` 包装 ID，只清远端来源，保留有 NBW 映射的本站 `p_` / `c_` 内容。
5. 注册后完成连接页回主页；从设置进入只关闭当前页。只读模式保留进入远端评论/详情的阅读入口。

## 接入与发布边界

**测试远端功能必须配套本轮新后端。** 旧生产后端不会理解协议头的隔离含义；尤其回复已有本站镜像 `p_` 时，旧服务器仍可能进入其 V1 同步逻辑。因此，不能拿该测试包连接旧生产服务来证明 V2-only 闭环，也不应在旧生产服务上进行远端写验收。

本轮不部署 Worker、不执行生产迁移、不配置生产 V2 Key/AES Key、不修改正式下载 JSON/R2/GitHub Release，不推进 Android `main`。全局三模式管理由后端独立管理员 API 提供；现有网页管理卡片仍只是旧版精确版本列表的开关，尚未新增三态图形界面。

真实 OAuth 授权、双方账号写入/撤销/删除、支付或其他用户业务数据均未代用户操作。正式启用仍需独立授权、后端配置和真实设备验收。
