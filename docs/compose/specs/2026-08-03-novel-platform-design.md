# ABDL Space 小说平台设计

## [S1] 目标与首期范围

在 ABDL Space Android App 内新增用户可见名称为“小说”的完整电子书能力。首期同时交付两条主链路：

- 私人云书架：登录用户导入 TXT、EPUB 或粘贴文本，完成云上传、云获取、离线整书缓存、阅读进度、书签和笔记跨设备同步。私人上传仅本人可见，不进入公开书城或互动系统。
- 作者创作发布：符合资格的用户在 App 内创建作品、分卷和章节，编辑纯文本段落，保存云草稿，经小米 MiMo 审核、评级后公开发布。

公开小说支持发现、搜索、收藏、点赞、评分、推荐和章节评论。小说入口位于首页右上角液态菜单，不修改现有五项底部导航。

首期不支持 PDF、章节插图、富文本正文、网页创作中心或第三方公开文件分享。

## [S2] 平台与兼容性

全 App 的 `minSdk` 从 24 提升到 33，只支持 Android 13及以上。`compileSdk` 和 `targetSdk` 继续按项目当前版本或后续构建要求升级，不因小说模块降低。

阅读器基于 `HuZaiGong/flowreader` 改造。FlowReader 与 ABDL Space 均使用 GPL-3.0，允许在保留版权、来源和许可证声明的前提下复制和修改。不得将上游完整 App 壳直接嵌入；应抽取并维护阅读、解析和本地书库能力，移除上游应用级导航和与 ABDL 重复的宿主逻辑。

## [S3] Android 模块边界

新增独立阅读模块，例如 `:reader-core`，包含：

- TXT/EPUB 解析、编码检测、目录和章节索引。
- FlowReader 分页、排版、主题、翻页和阅读位置锚点能力。
- 改造后的 Room 本地书库、离线文件索引、下载状态、阅读位置、书签、笔记和分页缓存。
- 与具体账号、网络端点和页面导航无关的接口。

`mastodon` 模块内新增 `novel` 业务域，包含公开书城、私人书架、作品详情、创作中心、章节编辑、互动、网络 DTO、云同步和账号隔离。小说主界面使用独立 `ComponentActivity` 承载 Compose，降低 AppKit Fragment 与 Compose 生命周期耦合。

Room 是设备本地镜像和离线数据源，云端是跨设备数据、权限和公开状态的权威来源。Room 中所有云对象必须带 `accountId`，禁止不同登录账号共享私人书籍、草稿、进度、书签、笔记或下载状态。

## [S4] Miuix 与阅读界面

小说首页、书卡、分段页签、搜索、筛选、表单、创作工具栏、设置和弹窗使用 `/home/ZYongX/projects/miuix` 对应依赖与现有 ABDL Miuix 主题能力，完整适配浅色和深色模式。

阅读正文保留 FlowReader 的低干扰视觉基线。正文区域不使用持续动态背景、重度实时模糊或液态玻璃，以保护长时间阅读的帧率、功耗和可读性。目录、设置、笔记和评论等非正文面板可使用 Miuix 风格。

## [S5] 页面与导航

首页右上角液态菜单新增“小说”。点击后进入小说首页，包含：

- 推荐：推荐流、分类、搜索、评级与内容提示、作品详情、点赞、评分和收藏。
- 书架：公开收藏、私人上传、下载状态、最近阅读和同步状态。
- 创作：作品、分卷、章节、草稿、审核、发布和申诉状态。

阅读器提供目录、进度、主题、字号、行距、翻页、书签、笔记和离线状态。章节评论从阅读器非正文操作区进入独立页面或底部面板，不将实时评论叠加到正文。

## [S6] 私人书籍与对象上传

私人书籍元数据至少包含 owner、标题、作者、格式、对象 key、内容哈希、字节大小、解析状态、创建时间和更新时间。原始 TXT/EPUB 存储于对象存储。

上传采用 `authorize -> 客户端直传 -> complete`：

1. 后端校验登录账号、配额、格式、大小和 MIME，生成不可预测对象 key 与短时 PUT 授权。
2. 客户端直接上传，并禁止覆盖已有对象。
3. complete 由后端校验 owner、对象 key、实际大小、类型和完整性后才标记可用。

该协议复用现有 COS 媒体链路的安全原则，但小说表和 purpose 独立，不能把媒体 upload ID 当小说文件使用。粘贴文本由服务端规范化为 UTF-8 TXT 对象并进入相同的解析流程。

私人书籍永不出现在公开搜索、推荐、评分、点赞或评论接口。删除书籍时先撤销云端引用，再异步清理对象；客户端同步删除 Room 内容和离线文件。

## [S7] 公开作品与章节版本

公开作品使用以下逻辑实体：

- `novels`：作品基本信息、作者、封面、分类、简介、状态和当前评级。
- `volumes`：分卷及排序。
- `chapters`：稳定章节身份、排序和当前公开 revision。
- `chapter_revisions`：草稿正文、不可变审核快照引用、审核状态、评级、内容提示和版本信息。

正文当前版本存 D1，提交审核时生成不可变对象快照，用于审核证据、回滚和离线分发。已发布章节修改时创建新 revision；旧 revision 在新版本审核通过前继续公开。切换当前 revision 必须事务性完成，禁止读者看到半发布状态。

纯文本正文只支持段落、章节标题和分隔线等受控结构，不支持 HTML、Markdown、脚本、富文本或章节插图。

## [S8] 作者资格与创作流程

后端实时判定创建和发布资格：账号注册已满72小时，并且至少发布过1条未删除帖子。客户端提示仅用于体验，不能作为权限依据。

满足条件后无需人工开通即可进入创作。资格只限制新建作品和提交发布；若作者之后删除帖子，不删除已有草稿或已发布作品。

编辑器本地优先：每次编辑先写 Room，再将同一 revision 增量同步到云端。断网时可持续编辑。两个设备并发修改同一 revision 时不得静默 last-write-wins；服务端返回版本冲突，保留本地与云端两个草稿并由作者选择或手工合并。

## [S9] MiMo 审核、评级与申诉

MiMo 只由后端调用，模型凭证通过 Worker Secret 管理，不下发 Android。提交审核后固定正文快照，模型必须返回符合 JSON Schema 的结构化结果：

- 是否属于过分违规。
- 风险类别与置信度。
- 建议评级。
- 面向读者的内容提示。
- 不包含大段原文的安全审核摘要。

模型调用失败、超时或输出不合法时保持 `review_pending`，不得默认放行。

评级参考美国电影分级思路，但使用小说场景的本地标签：`全年龄`、`建议12+`、`建议15+`、`建议18+`。评级和内容提示只展示，不按账号年龄限制阅读，也不使用暗示官方 MPA/MPAA 认证的名称或标志。

过分违规则拒绝公开，但保留作者私有草稿。作者可修改后创建新 revision 重审，或提交人工申诉。申诉不得仅由同一个模型自动裁决。审核、评级、申诉和发布动作均写入审计记录。

## [S10] 云同步与冲突

服务端按账号保存阅读位置、书签、笔记和更新时间；Room 保存完整本地镜像。同步对象使用客户端生成的稳定 ID。

- 阅读位置：按书籍节流上传，记录章节 revision、章节内锚点和最后阅读时间；不得只在退出页面时同步。
- 书签和笔记：普通更新采用 `updated_at` 的 last-write-wins。
- 删除：写入 tombstone 并保留足够同步窗口，避免离线设备恢复已删除数据。
- 章节更新：书签和笔记锚点尽量映射到新 revision；无法映射时保留原文摘要并标记需要重新定位。
- 账号切换：停止旧账号同步任务，关闭或切换 Room 作用域，清除旧账号内存状态后再加载新账号。

同步 API 必须分页并支持从游标增量获取，不能每次下载整套书架状态。

## [S11] 离线缓存与更新

公开收藏和私人书籍均可显式下载整书。公开书按不可变 chapter revision 快照缓存；私人书按内容哈希缓存原始文件和解析结果。

下载采用临时文件、完整性校验和原子重命名，失败或取消不得留下被识别为完整书籍的文件。相同 owner 与内容哈希的私人上传可提示重复，不能跨用户暴露去重结果。

公开章节出现新 revision 时提示可更新。正在阅读的离线版本不被静默替换；用户确认或退出本次阅读后再切换，并保留旧版本直到新版本完整校验成功。

## [S12] 互动与推荐

公开作品支持收藏、作品点赞、单用户评分和章节评论。私人书籍不得调用互动 API。

收藏、点赞和评分使用 `(account_id, target_id)` 唯一约束并提供幂等接口。评分保存单用户最新值，聚合数量和平均分由服务端计算。评论支持删除、举报和分页，所有作者身份来自认证会话。

推荐首期使用可解释的规则排序，将更新活跃度、收藏、点赞、评分和阅读完成度纳入，但必须限制单项权重并过滤下架、审核中和拒绝作品。后续可替换推荐算法，不改变客户端契约。

## [S13] 安全、隐私与可靠性

- 所有小说接口从已验证会话取得账号，禁止信任客户端传入 owner 或 author ID。
- 私人对象和草稿必须通过鉴权 API 或短时授权访问，不能使用永久公开 URL。
- 上传限制格式、大小、解压后总体积、文件数、路径穿越和压缩比，防止恶意 EPUB/ZIP。
- TXT 做编码、控制字符和超长行限制；EPUB 解析禁用脚本和外部资源请求。
- MiMo 审核日志不得记录模型密钥或完整敏感正文；审计快照按权限访问。
- 评论、作品和作者支持举报与后台下架；下架不立即销毁证据和作者私有稿。
- 对象、D1 行和 Room 文件都有稳定清理策略，失败任务可安全重试。

## [S14] API 边界

后端新增独立 `/api/v1/novels/...` 域，至少覆盖：

- 私人书籍 authorize、complete、list、detail、delete 和 download authorization。
- 公开作品 list、search、detail、volumes、chapters 和 chapter content。
- 创作作品、分卷、章节、revision 草稿同步、提交审核、审核状态和申诉。
- 收藏、点赞、评分、评论和举报。
- 阅读位置、书签、笔记和增量同步。

DTO 使用 snake_case，与现有 Gson 命名策略保持一致。列表使用稳定 cursor 分页。创建、上传完成、草稿同步、发布和互动写操作支持幂等键。

## [S15] 测试与验收

后端自动化测试至少覆盖：

- 私人书籍跨账号不可见，不能进入公开接口。
- 上传授权、对象大小/MIME/哈希校验、覆盖阻止和恶意 EPUB 限制。
- 作者72小时与至少1帖资格边界。
- 模型失败和非法输出不放行，过分违规则拒绝，申诉进入人工队列。
- 已发布章节在新 revision 审核前保持旧版，审核通过后原子切换。
- 收藏、点赞、评分幂等与评论权限。
- 同步游标、tombstone、版本冲突和账号隔离。

Android 自动化测试至少覆盖 Room migration、账号作用域、解析器、分页锚点、断网编辑、冲突保留、下载原子性、进度节流和关键 Compose 状态。

真机验收覆盖 Android 13及以上代表设备、大型 EPUB、超长 TXT/章节、浅色/深色、断网编辑、上传取消、跨设备同步、账号切换、离线整书、章节更新、长时间阅读性能和内存占用。

## [S16] 分批实施与发布门禁

两条主链路在同一首期版本开放，但按以下顺序实施和验收：

1. 后端 schema、对象协议、同步协议与 Android Room/reader-core 基础。
2. 私人云书架、TXT/EPUB/粘贴导入、离线整书和阅读同步。
3. 创作中心、草稿冲突、MiMo 审核、评级、发布和申诉。
4. 公开书城、收藏、点赞、评分、评论和规则推荐。
5. 全链路安全审查、数据迁移、性能测试和真机验收。

任一阶段不得以 Mock 成功替代真实对象存储、D1、MiMo失败路径和跨设备同步验收。最终发布前必须完成后端部署、Android Release构建和至少一轮真实账号端到端验证。
