# 小说自定义封面稳定性修复（2026-11-11）

## 范围与基线

用户报告小说相关页面在自定义图片与文字封面间反复切换。本轮明确基于用户指定的 `2dac60b44e17a10e330871d64e3ab06b1e5aae25`（v5），工作分支 `fix/novel-cover-stability-20261111`。不带回 v6 截图冻结/去行模糊、不采用两叶实验、不改阅读器、后端、封面上传协议或版本号。

书城、书架、搜索、详情、作者/创作者与作品管理页的远程封面使用共用 `NovelRemoteCover`；编辑页也经同一层。时间线小说卡是独立 AppKit 适配层，本轮只回归、不据未复现的迟到失败推断修改其生产逻辑。

## 已修复的加载状态缺口

1. **成功结果不再依赖临时 View 仍在场。** AppKit 合法完成时先交当前账号作用域，再通知订阅者；500ms 短暂离屏期内先完成、后重建 View，也可同步恢复成功图片，不重新淡入。
2. **已完成源与解码缓存分离。** 保留当前作用域下成功的磁盘源标识；12MiB 位图 LRU 淘汰解码图后，同一完整书籍/投影/URL 可以从已有 AppKit 磁盘源读取，不必重新下载。源记录仍有64条上限，不增加位图预算。
3. **共享请求按实际结果计数。** 同一次失败只消耗一次重试预算，不按每个 View 重复计数；成功清除对应已恢复的失败记录，永久失败仍有界停止。
4. **失效时保留原隔离。** 请求取消/失败后仍使用新 attempt key，防止重新加入 AppKit 尚未完成取消的 source。换 URL/投影、移除、退出/会话失效拒绝迟到结果；不剥签名参数、不共用其他账号图片。
5. **多位置与元数据淘汰保护。** 同一封面更新在多个位置只推进一次实体世代；新工厂观察到旧 URL 后再次更新仍正确失效。世代元数据淘汰不丢掉仍被 live binding 使用的世代。

- `NovelCoverHttpCancellationTest`：真实 `needsDiskCache=true` AppKit 路径，短离屏完成后再订阅、三位置共用一次失败并恢复、取消 worker 竞态、timeout、有界重试；10张500×700图实际超出12MiB并验证淘汰后磁盘复用。
