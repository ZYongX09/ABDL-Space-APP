# 详情加载、首页历史与无缝动画

本记录跟随2026-11-02追加需求。先收尾英文与帖子翻译，再完成本轮界面工作；用户已明确暂缓出测试包。仅开发分支提交、合回并推送develop；不自动main、正式发版、生产配置或设备安装。

## 用户确认的范围

1. 帖子详情待请求区域使用流光骨架。既有列表→详情已经传递Status和作者资料，用户补充该传递任务可不做，因此不重复实现或另造跨页缓存。
2. 打开App主页先展示本账号历史帖子，顶部使用纯文本小组件“正在刷新中......”，获取新结果后替换；不是只显示大加载动画。
3. 在帖子、小说卡、相册卡等合适入口接入无缝动画，考虑旧Android、厂商ROM与设置开关。非支持设备保持原导航，不把普通Fragment动效冒充系统KIT。

## 现有机制核实

- `StatusListFragment.onItemClick`经`BaseStatusListFragment.navigateToStatus`将clone后的Status及已有回复账号传给`ThreadFragment`；详情会直接构建主帖并显示。仅context/回复部分等待网络。
- 主页默认FOLLOWING实际调用`/api/v1/timelines/all`并读取Link中的opaque max_id。旧`CacheController.getHomeTimeline`走`/timelines/home`且按时间/ID排序，不能直接用于混合聚合流。
- AppKit首轮40条可拆成20条显示和20条预载，hydrate历史与网络两次走普通append会重复；刷新须权威替换并同时处理预载和游标。

## 实施约束

### 详情骨架

只修改Thread本页的全页/回复footer加载布局，保留AppKit错误与重试ID。已有主帖继续显示，不用假文字代替真正已取得内容。动画遵守降低动态效果与系统动画设置，隐藏/销毁后停止；静态骨架也表达加载状态。成功、空回复、错误、取消、重试、异步NBW context和迟到回包均需真实生命周期回归。

### 首页历史

使用当前账号私库的独立、有序、有限首屏快照，含格式、时间和原样游标；不混用旧home表。账号/session/generation隔离，坏数据或过期记录丢弃，不因异步写入复活已注销数据库。成功空结果也替换旧历史；短时断网保留历史但结束刷新标记，鉴权失败与普通断网区分。

缓存不是当前资源权限证明。删除、屏蔽、静音、NBW策略变更等需要失效；历史展示期间不能触发自动AI翻译或用陈旧引用批量补取内容。新帖子提示原逻辑独立保留；刷新提示不放在液态模式会隐藏的原按钮容器中。

### 无缝动画

已先阅读`~/projects/SharedViewDemo/README.md`并静态核对本地SDK。真实能力由ROM提供，SDK门面将完整V1 ABI与enabled状态映射为支持协议。不能只按设备品牌/Android版本猜测支持。

本地Demo为MIT，但SDK另有独立授权说明，AAR未找到明确再分发许可。本轮不复制AAR、不接HTTP Maven仓、不使用动态`+`；按已核实的公开ROM ABI做无二进制依赖的兼容探测，失败安全退回原导航。此做法不构成厂商所有条款均已法律确认的声明。

仅运行时完整支持的设备显示开关。旧Android、不支持ROM、用户关闭、降低动态效果、动画比例关闭、源已回收、应用锁、secure窗口或受保护相册均不得勉强截图。不能临时清除FLAG_SECURE。

帖子由多行Recycler项构成，应基于同一帖子真实可见范围，而非一个正文holder冒充整卡；截图有像素/内存预算、不持久化。跨Activity参数须限制Binder体积，大内容回退原Fragment导航，不新增用户已取消的缓存传递设计。

返回前校验account/entity/source binding与临时会话，按ROM声明的SCREEN/WINDOW坐标更新位置，在finish之前刷新返回配置。原View失效则降级而非闪跳到错误帖子；进程重建没有返回目标时仍须可正常退出。小说只对外部详情入口建立退出边界，内部章节/作者导航不应每次back就结束动画。
